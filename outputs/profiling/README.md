# Phase 1 profiling outputs

These files were generated by:

```bash
python -m src.profiling.profile_identifiers --data-dir data/generated --output-dir outputs/profiling
```

| Artifact | Purpose | Git policy |
|---|---|---|
| `source_summary.csv` | Parsed and expected source row counts | Committed |
| `column_profile.csv` | Missingness, distinctness, uniqueness, duplicates, maxima, and frequency bands | Committed |
| `identifier_frequency.csv` | Raw value, profiling key, source frequency, and global frequency | Generated locally |
| `worthless_values.csv` | Stakeholder-safe masked Rule 2 registry | Committed |
| `rule2_registry.json` | Machine registry retaining later-use profiling keys | Committed |
| `data_quality_summary.json` | Metrics, risks, observations, and limitations | Committed |
| `profiling_report.md` | Concise stakeholder report | Committed |

`identifier_frequency.csv` contains 1,595,336 rows and is approximately 147.3 MiB. It is
excluded from Git because it exceeds GitHub's 100 MiB per-file limit, but it is regenerated
by the command above. CSV is used as a streaming-friendly format; the profiler uses a
temporary SQLite aggregation database and deletes it after a successful run.

The JSON registry contains internal profiling keys. Stakeholder-facing CSV and Markdown
outputs expose only masked values and deterministic hashes.
